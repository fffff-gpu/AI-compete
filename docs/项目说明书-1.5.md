## 0. 一页结论

**做了什么**：把"每轮从父检查点续训一次"这件小事做成一个**受控闭环**——先监测与归因漂移，
再在**封闭动作空间**里让大模型选一个已挖掘好的配方，训练后由门禁按"分段增益 + 最差段不退"判定
采纳或回退，被拒轮次不污染下一轮起点。整轮不需要人工，不需要外网，不需要额外标注。

**结果**（官方静态基线 → 本系统 1.5，验证集口径）：

| 数据 | 指标 | 静态基线 | 本系统 | 增益 | 显著性 | 最差段 |
|---|---|---|---|---|---|---|
| A 气体六分类 | Macro-F1 ↑ | 0.7140 | **0.7258** | +0.0086 | 0.44σ（不显著，如实标注） | 0（合规空间内不可达） |
| B 轴承 RUL | RMSE ↓ | 681.1598 | **497.7463** | +183.41（+26.9%） | ≈20σ | +169.76 |
| C 发动机 RUL | RMSE ↓ | 52.8686 | **51.4884** | +2.61% | 配对 bootstrap 下界 > 0 | +1.25 |

**成本**：10 轮训练在 2 核 CPU 上总耗时十几秒到二十秒级；新增人工标注 **0 条**；
大模型每轮 1 次调用、10 轮合计约 5–6k token（1.4 实测 10,910 token 为上限对照）。

**边界**：A 的"最差阶段"在题目允许的动作空间内**数学上不可达**（§1.3 给了证明）；
C 的漂移归因在两例上与工况切换混淆（§4.4 如实披露）。我们把这些写成结论，而不是藏起来。

## 1. 问题背景与技术路线论证

### 1.1 评分公式决定了"能做多少"

客观分 G 按阶段计算：`G = (系统 − 静态基线) / (全量重训上界 − 静态基线)`，段均后给分；
另有"最差阶段与恢复速度""历史工况回测保持""资源效率（算力/标注/token）"三项。
这条公式隐含两个约束：

1. **分母是"每阶段全量重训上界"**。只有能逼近重训的更新方式才拿得到高分，
   纯静态或纯微调都不行——系统必须**真的在每轮吸收新数据**。
2. **最差阶段单独计分**。只在平均上好看、末段崩掉的方案会被扣，
   所以门禁里"最差段不退"是硬条件，不是修辞。

### 1.2 三条候选路线，为什么选"封闭配方 + 受控续训"

| 路线 | 做法 | 问题 | 结论 |
|---|---|---|---|
| 全量重训 | 每轮从零训 | 算力最高、无历史保持、无"自进化"叙事 | 只作对照上界 |
| 自由超参搜索 | 每轮让 LLM 给任意超参 | 动作空间无界，坏动作会累积损伤；离线不可复现 | 否 |
| **封闭配方 + 受控续训** | 预挖掘 4 个配方，LLM 只做"选哪个、几轮" | 需要先做数据挖掘，动作空间小但可控 | **采用** |

4 个配方来自 B/C 两个数据集上的离线挖掘（任务 B 的 6 个发现、任务 C 的误差形状分析），
每个配方都是"在某类漂移下反复验证过"的配置，LLM 的自由度被压到
"4 选 1 + epochs 1..16"，**任何输出都能被安全执行**。

### 1.3 A 的不可达性（否定结论，也是主要产出）

对 A 做线性探针与逐阶段误差分解后可证：在题目允许的**续训 + 配方**动作空间内，
A 的第三阶段增益上界低于门禁 `min_gain=0.002`。也就是说"最差阶段"这一项对 A
不是调参问题，而是**信息问题**：该段的标签分布与特征之间没有可被这套模型族利用的额外信号。
所以系统对 A 的策略是**不劣化**（只采纳第 1 轮 +0.0086，之后保持），而不是硬刷分。
这一结论写进了《技术报告》§4.11，也决定了 1.5 里 A 的默认配方是 `official`（最短、最稳）。

### 1.4 为什么不新训大模型

- **精度不来自 LLM**：A/B/C 的增益全部来自 rulkit 配方（B 的 +183 是 20σ 级），
  LLM 只在 4 个配方里选一个，选错也只是少赚，不会破坏结果。
- **token 已经很省**：1.5 每轮输入约 610 字符、输出 ≤600 token，10 轮合计 5–6k，
  再压缩的空间远小于"把配方挖掘做对"的收益。
- **已有微调证据但不可迁移**：校内赛阶段做过 Qwen3.8-27B LoRA SFT（rank 32、2 epoch、
  93 条、73,649 token ≈ ¥0.66），在线三臂对比显示微调模型的**单位算力增益是基座的 2.0–2.7 倍**、
  token 从 9,044 降到 7,604；但那批数据是旧项目的 gas 数据流，不是本赛道 A/B/C 投影，
  直接搬来当赛道证据不诚实，因此只作为"决策模型后训练"的加分证据保留（§6.3）。

## 2. 系统架构

### 2.1 分层

```
┌──────────────────────────────────────────────────────────────┐
│ 平台（评测/计量/隐藏标签）                                     │
│   · 每轮注入 /data（公开投影）、/previous（父产物）、/state     │
│   · 提供宿主模型网关（rnd.model），密钥与端点都在平台侧         │
└───────────────▲──────────────────────────┬───────────────────┘
                │ SUBMIT_CANDIDATE/FINISH  │ start 帧 / 样本行
┌───────────────┴──────────────────────────▼───────────────────┐
│ 镜像 zhixun-harness:1.5（linux/amd64，2 核，离线）             │
│  /app/harness.py        协议入口（describe/train/predict）     │
│  /app/contest_submission.py  选手模块                          │
│    ├─ rulkit/data.py    投影读取与强校验（禁止目标派生字段）    │
│    ├─ rulkit/model.py   865~4326 参数 MLP + 配方开关            │
│    ├─ monitor           KS 漂移统计与归因（离线/回放）          │
│    ├─ control/governance 门禁 v1/v2、动作白名单、六不变量        │
│    └─ memory/records    跨轮记忆、账本、审计链                  │
│  /workspace             唯一可写（候选目录）                    │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 一轮的时序（协议 `contest.harness.workspace.v2`）

1. 宿主起容器，`train` 收到 `start` 帧（`round_index`、`dataset_key`、`task`、`max_output_tokens`…）；
2. 从 `/previous` 读父 `checkpoint.npz`，校验 `checkpoint_sha256`（不符即 `PARENT_DIGEST_MISMATCH`，不解释、不修补）；
3. 读 `/data/train.jsonl`、`/data/validation.jsonl`，校验 schema 与父模型 `meta.paths` 一致；
4. **一次强制真实模型调用**：把状态与 4 个候选配方给大模型，`temperature=0`、`max_tokens=min(600, 上限)`，
   拿回 `{recipe, epochs, hypothesis, change_summary}`；解析失败即回默认配方并把原因写进 `configuration.parse`；
5. 设环境变量应用配方 → 从父检查点续训 → 可选 SWA → 在公开验证集上算 before/after；
6. 写 `candidate-r{N}/checkpoint.npz` 与 `recipe.json`，`submit_candidate` 上报；
7. `finish` 携带该轮 `model_call_id` 与理由，**完成这一轮**；
8. 宿主用隐藏验证集评分并决定采纳；被拒则下一轮仍从上一轮被采纳的产物出发（`I1` 不变量）。

### 2.3 为什么这个架构"离线也能跑"

- 镜像内**没有**数据、权重、密钥、端点；`/app` 只读，唯一可写是 `/workspace`；
- 模型调用走宿主网关（本地 OpenAI 兼容代理，`api_key` 是占位符 `workspace-local-no-secret`），
  镜像里没有真实凭据，评测环境断外网也不影响；
- 依赖只有 `numpy==1.26.4`，线程固定 1，无 GPU、无网络下载、无非确定性时间戳。

## 3. 漂移监测与诊断

### 3.1 监测：用能被解释的统计量

- **参考窗**：每轮取公开验证集**前 25%**（`ref_stop = max(32, n//4)`）作参考分布，
  其余作当前窗；不引入外部参考数据。
- **统计量**：逐特征两样本 KS，归一化为 `KS × sqrt(nm/(n+m))`，取 **Top-3 特征均值**作漂移分数。
  选 Top-3 而不是全体，是为了让"少数特征真漂"不被大量稳定特征稀释。
- **阈值自举**：在参考窗内做 24 次重采样，取 `warn = max(q95×1.05, 0.05)`、
  `alarm = max(q99.5×1.05, warn×1.5)`。阈值随数据规模自适应，不写死。
- **输出**：`{level: ok|warn|alarm, score, top_features, attribution}`，进 `records` 账本。

### 3.2 诊断：协变量漂移 / 概念漂移 / 混合

`classify_drift` 用两条证据交叉判定：

| 证据 | 判定 |
|---|---|
| 特征分布 KS 显著、标签条件分布稳定 | `covariate`（输入变了，规则没变） |
| 标签位移显著（残差/标签均值漂移）、特征分布稳定 | `concept`（规则变了） |
| 两者同时成立 | `mixed` |

判定结果决定"这一轮该不该花"：`covariate` 偏重加权/重采样，`concept` 偏重续训与末端加权，
`mixed` 走保守配方。这是把"监测"接到"动作"上的关键一环，而不是只报警。

### 3.3 监测基准（合成漂移流）

| 数据 | 构造的漂移类型 | 判对 |
|---|---|---|
| A | 4 种（特征缩放、噪声、类别比例、混合） | 4/4 |
| B | 4 种（工况切换、退化速率、噪声、混合） | 4/4 |
| C | 4 种 | **2/4** |

### 3.4 C 的失败与解释（如实披露）

C 上"工况切换"与"P(x) 漂移"在**行级 KS 统计量上同值**（都是 1.85），
在只看单特征边际分布的口径下不可区分，归因退化为 `mixed`，因此 4 例判对 2 例。
这不是阈值没调好：要分开必须引入**条件分布**或**时序结构**证据（例如按窗口切分的
条件 KS、退化轨迹斜率），这超出当前 2 核/4GiB 预算下可稳定实现的范畴，故保留为已知局限。

## 4. 模型更新与受控自改进方案

### 4.1 动作空间（封闭、可枚举、可回滚）

| 轴 | 取值 | 说明 |
|---|---|---|
| 配方 | `official` / `center035_sev2_end` / `center04_end` / `long_train_swa` | 4 个，全部离线挖掘并复验 |
| epochs | 1..16 | 上限 16 防止过训；默认按数据集给 |
| 其余超参 | **不可改** | LR/L2/平滑/扰动/SWA/谱加权都在配方里固化 |

LLM 的输出只有 `recipe` 与 `epochs` 两个字段能生效，其余（理由、假设、变更摘要）
只进账本供审计。**未知配方名 → 回默认配方**，不报错、不中断。

### 4.2 门禁：v1 到 v2 的演进

- **v1**：`gain ≥ min_gain` 且 `worst_gain ≥ −worst_tol×静态值`
  （`min_gain`：A 0.002 / B 5.0 / C 0.5；`worst_tol = 0.02`）。
- **v2**：把"单次验证集数字"换成**下界判断**——多轨迹均值减 `k·se`，再加配对 bootstrap 下界 > 0，
  降低小验证集上的误采纳。
- 效果：A 集有门禁 0.7258、无门禁 0.6296，**门禁本身贡献 9.6 个点**；
  B 集有门禁 497.75、无门禁 648.88（平均好看但末段 −108.6，被门禁拦下）。

### 4.3 六条不变量（治理层强制）

| 编号 | 不变量 | 作用 |
|---|---|---|
| I1 | 被拒轮次不作下一轮起点 | 坏动作的影响半径 = 1 轮 |
| I2 | 父检查点摘要不符即拒跑 | 防"补造元信息" |
| I3 | 训练只读 `/data`，监测只用 validation | 防标签泄漏 |
| I4 | 候选产物只写 `/workspace` | 父产物与数据全程只读 |
| I5 | 每轮恰好一次真实模型调用 | 决策可追溯、可计费 |
| I6 | `finish` 必带 `model_call_id` | 无调用不能"空手交卷" |

### 4.4 记忆与"自改进"的边界

`memory` 记录每轮"漂移类型 → 配方 → 增益"的三元组，供下一轮参考（例如同一数据集
连续两轮 `concept` 漂移则偏向更长训练）。但**记忆不能越过门禁**：它只影响候选，
不影响采纳判定。所谓"自改进"被严格定义为"在固定动作空间内，用历史证据改善选择"，
而不是"系统自己改自己的规则"——后者在工业场景不可审计，我们不采用。

### 4.5 回滚

三级：回配方（秒级，不断轮）→ 回检查点（单轮，门禁直接回退父产物）→ 回镜像
（`docker load` 官方基线或 1.3 归档）。三级都不需要人工修数据。

### 4.6 1.5.1 补丁：任务门控、探针测量与三级回退

初版 1.5 在平台预检中被指出三处缺陷，1.5.1 全部修掉，并把修复过程写进交付材料：

| 缺陷（平台预检原文要点） | 根因 | 修复 |
|---|---|---|
| C 集四个配方都抛 `AttributeError: recipe_notes` | `finish_swa` 在平均后清空 `recipe_notes`，而 `fit` 的 sev-skip 分支要 append | `fit` 懒初始化该字段、`finish_swa` 只清 SWA 状态、`load` 显式置空 |
| A 集可能选到中心化损失配方，训练直接失败 | 配方空间未按任务过滤，4 个配方对分类并不都合法 | `ALLOWED_BY_TASK`：分类只 `official` / `long_train_swa`，回归 4 个；越界即回落默认并标记 `recipe-defaulted` |
| 决策只看行数与父元信息，没有当轮实测 | `_choose` 的输入缺验证指标 | 决策前先测当前检查点（accuracy+macro_f1 或 rmse+mae）；无验证集时按 id 哈希抽 20%（≤512 行）做探针 `holdout-1/5` |

另外加了三级回退：所选配方异常 → 重载父检查点改跑默认配方 → 再失败跑 `official`，
`attempts`（哪一级、什么异常）落进 `recipe.json` 与 `configuration`，供审计与复盘。
本地用进程内 Harness 替身走真实 `Round` 协议复跑 3 数据集 × 4 配方共 12 组，
再加 3 组无验证集探针路径，**12/12 与 3/3 全通过**；A 的三个 center 请求全部被门控改成
`official`，C 记录 `sev_skipped:no-vertical-spectral-column` 后正常完成。

## 5. 静态基线对照与性能提升

### 5.1 对照口径

所有数字都在**同一份公开投影、同一隐藏验证集、同一评分公式**下取得；
"静态基线"指官方 baseline 不更新直接评测；"全量重训上界"仅作 G 的分母参照。

### 5.2 三数据集结果

| 数据 | 指标 | 静态基线 | 1.3 | **1.5** | 三段增益（1.5） | 最差段 | 采纳轮次 |
|---|---|---|---|---|---|---|---|
| A | Macro-F1 ↑ | 0.7140 | 0.7258 | **0.7258** | +0.0086 / 0 / 0 | 0 | 1/10 |
| B | RMSE ↓ | 681.1598 | 507.4812 | **497.7463** | +287.89 / +181.72 / +169.76 | +169.76 | 1/10（首轮即最优） |
| C | RMSE ↓ | 52.8686 | 52.1424 | **51.4884** | 逐段为正 | +1.25 | 2/10 |

### 5.3 提升来自哪里（可解释的归因）

- **B 的 +183（20σ）**：来自三件事的叠加——中心化损失（同一 batch 内按轴承去均值、
  梯度 stop-gradient）、末端谱能量方差加权（`sev_end`）、末 2 epoch SWA。
  消融显示：只上中心化损失约 +120，再加末端加权 +40，SWA 补最后约 +20。
- **C 的 +2.61%**：来自"误差形状"分析——C 的残差随循环数呈系统性弯曲，
  长训练 + SWA 把弯曲压平；门禁保证只在末段不退时采纳。
- **A 的 +0.0086**：第一轮 `official` 顺带带来的小幅提升，之后保持。A 的价值在"证明系统
  在信息不足时**不乱动**"，而不是刷分。

### 5.4 与"无门禁/无监测"的对照

| 配置 | A | B | C | 说明 |
|---|---|---|---|---|
| 静态基线 | 0.7140 | 681.16 | 52.87 | 不更新 |
| 全采纳（无门禁） | 0.6296 | 648.88 | 52.14 | 平均尚可，最差段崩 |
| **本系统（有门禁 + 监测）** | **0.7258** | **497.75** | **51.49** | 分段与最差段都稳 |

## 6. 算力、标注与 Token 消耗

### 6.1 三本账

| 账 | 用量 | 口径 |
|---|---|---|
| 算力 | 2 核 CPU / 4 GiB；10 轮训练总耗时十几秒到二十秒级（实测 0.1–18.6 s/run） | 平台计量 `cost_units`：常规轮 0，v2 门禁的 bootstrap 轮 63.3–226.9 |
| 标注 | **新增人工标注 0 条**；只用平台公开投影的 validation 前 25% 作参考窗 | 标注配额未被消耗 |
| Token | 每轮 1 次调用；1.5 单轮输入约 610 字符、输出 ≤600 token；10 轮合计 **5–6k** | 1.4 对照：修复后 9,521 输入 + 1,389 输出 = 10,910（含 10 次调用） |

### 6.2 资源效率的含义

评分把"单位增益的算力/标注/token"按全体排名分档。本系统的取舍是：
**用极小的模型（865~4326 参数）和极短的训练（秒级）换取绝大部分增益**，
把昂贵的资源（大模型、重复重训）只用在"选配方"这一件必须判断的事上。
在 B 上，单位算力增益约为"每 100 秒训练换 18.3 RMSE"，而全量重训需要数倍算力。

### 6.3 微调（决策模型后训练）的证据与定位

| 臂（旧 gas 流，同 seed） | acc | G | 单位增益 | token |
|---|---|---|---|---|
| 规则 | 0.7174 | 0.7088 | 0.0492 | — |
| 基座 Qwen3.8-27B | 0.7053 | 0.6914 | 0.1223 | 9,044 |
| LoRA 微调（P5） | 0.6851 | 0.6503 | 0.2451 | 7,604 |

微调保留基座约 93% 的增益、成本约一半，**单位算力增益是基座的 2.0–2.7 倍**；
离线留出 10 条上，微调把 `exact_ok` 从 0.00 提到 0.70（基座一律给 `retrain`）。
但这是旧数据流，且 `temperature=0` 仍有远端抖动（两次复跑 acc 0.6851 → 0.6934），
故**不作为本赛道的默认决策器**，只在加分项里作为"受控后训练"的方法证据。

平台侧可复核（2026-11-19）：PyTRIO 控制面共 7 条训练记录，`base_model` 均为 `Qwen/Qwen3.8-27B`、
LoRA rank 32；P5 权重为 `trio://run_t46dhdn3u72b/sampler_weights/zhixun-policy-v1`
（checkpoint `ckpt_x73ov3ws41yh`，SAMPLER，step 48，1.15 GB）。该权重 `status=LOCAL`、
`is_uploaded=false`，即仅在本工作区可用；若评测环境无法按持久 Sampler 加载，
决策模型回落到 `Qwen/Qwen3.8-27B` 基础模型，系统行为不变（配方空间、门禁、回退均与模型身份解耦）。

## 7. 安全控制与工业落地价值

### 7.1 安全控制（可审计、可回滚、可离线）

| 风险 | 控制 |
|---|---|
| 坏动作损伤模型 | 门禁 + `I1`：坏动作影响半径 1 轮，回测保持率不下降 |
| 标签泄漏 / 隐藏集 | 训练只读 `/data/train`，监测只用 validation；禁止目标派生字段（`rul` 等） |
| 越权改环境 | 镜像内无密钥、无端点；`/app` 只读，产物只写 `/workspace` |
| 父产物被篡改 | `PARENT_DIGEST_MISMATCH` 直接拒跑，不修补 |
| 不可解释的"自改进" | 动作空间封闭（4 配方 × 16 epochs），记忆只影响候选不影响采纳 |
| 故障不可恢复 | 三级回滚（配方 / 检查点 / 镜像），均可离线完成 |
| 评测不可复现 | 线程固定 1、无时间戳、`temperature=0`、每轮账本落盘 |

### 7.2 工业落地价值

1. **迁移成本低**：换产线只需换 `/data` 投影与父检查点，配方与门禁参数可按新数据的
   `min_gain`/噪声重标定；不需要为新设备重训大模型。
2. **边际成本近乎为零**：每轮是一次秒级续训 + 一次极短模型调用，
   产线侧可以"每天一轮"甚至"每班一轮"，而不是"每季度重训一次"。
3. **可解释的决策链**：每轮都有 `hypothesis / change_summary / reason / model_call_id`，
   工艺工程师能读懂"为什么这轮换了这个配方"，这是产线愿意放权的前提。
4. **失败可承受**：最差情况是"这一轮不采纳"，而不是"模型被带坏"；
   对 7×24 产线，这是能不能上线的分水岭。
5. **诚实的能力边界**：A 的不可达与 C 的归因混淆都被写成结论，
   避免把"运气"包装成"能力"——工业客户最终会用自己的数据验证这一点。

### 7.3 局限与下一步

- C 的归因需要条件分布/时序证据，当前预算下未实现；
- v2 门禁的 bootstrap 让 `cost_units` 从 0 升到 63–227，需在"更稳"与"更省"之间按产线定档；
- 微调模型尚未进入评分路径（取决于平台是否允许 `trio://` sampler 作模型身份）；
- 三个数据集都是中小规模表格/序列，结论向图像/振动高维场景外推需重新验证。

## 附录 C：术语

- **投影（projection）**：平台每轮提供的公开训练/验证子集，特征已扁平化，不含目标派生字段。
- **配方（recipe）**：一组固化的训练超参组合，是系统唯一可选的"动作"。
- **门禁（gate）**：判定候选是否可被采纳的规则，同时看平均增益与最差段。
- **G**：官方客观分，按阶段归一化到"静态基线→全量重训上界"之间。
