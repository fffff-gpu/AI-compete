## 1.5.1 修了什么（平台预检三项缺陷）

| 缺陷 | 修复 |
|---|---|
| C 集四配方都抛 `AttributeError: 'Model' object has no attribute 'recipe_notes'` | `Model.fit` 懒初始化、`finish_swa` 不再清空、`load` 显式置空 |
| A 集可能选到中心化损失配方，训练直接失败 | `ALLOWED_BY_TASK`：分类只 `official` / `long_train_swa`，越界回落默认 |
| 决策没有当轮实测 | 决策前测当前检查点（accuracy+macro_f1 / rmse+mae；无验证集时 `holdout-1/5` 探针，≤512 行） |
| 执行异常直接判本轮失败 | 三级回退：默认配方 → 父检查点重载 → `official`，`attempts` 落盘 |

本地复现：进程内 Harness 替身走真实 `Round` 协议，3 数据集 × 4 配方 12 组 + 3 组探针路径，
`failures: 0`（脚本 `official/_scratch/repro_recipe_failures.py`）。

## 运行与复现

```bash
# 加载（manifest.json 带 RepoTags，加载后即为 zhixun-harness:1.5）
docker load -i zhixun-harness-1.5.tar
# 若显示 <none> 再命名：docker tag <image-id> zhixun-harness:1.5

# 协议自检：不需要数据、密钥与网络
docker run --rm --network none zhixun-harness:1.5
# 期望：{"protocol":"contest.harness.workspace.v2","model_access":"host_gateway_rpc",
#        "sdk":"contest_harness","sdk_version":"1.0.4","tasks":["classification","regression"]}
```

平台按轮注入 `/data/{train,validation}.jsonl`、`/previous`（父产物）、`/state`；选手只写 `/workspace`。
离线单独跑 `predict` 需自行挂载数据与父检查点，完整步骤见 `04-系统运行说明/系统运行说明-1.5.pdf`。

## 版本与口径

- 1.5.1 = 官方 Harness SDK 1.0.4（协议 `contest.harness.workspace.v2`）+ 平台预检修复。相对 1.4：入口改为 `python3 /app/harness.py`，每轮强制一次 `rnd.model()` 真实调用（否则 `MODEL_CALL_REQUIRED`）。
- 决策模型：平台白名单基础模型（Qwen3.8-27B）或队伍 `trio://` sampler；模型回复不可用或越界时回落默认配方，执行异常再走三级回退。
- 校内赛工程（旧 gas/C-MAPSS/XJTU 数据流、P0–P5 实验）已归档到 `归档/zhixun-校内赛-20261119/`，不作本次提交来源；其 LoRA 微调只作为「决策模型后训练」加分证据（见云记录末节）。
