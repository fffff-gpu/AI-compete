# 系统运行说明（企业赛 · 1.5.1）

**队伍**：智训引擎  **作品**：工业模型自进化 Harness
**镜像**：`zhixun-harness:1.5.1`（`docker save` 归档 `zhixun-harness-1.5.tar`，65,976,320 B，
sha256 `9ff79a47e240c0f7bb1df84de712c14090f4654139c629e66c80d9ecea9f3345`，12 层，linux/amd64）
**协议**：`contest.harness.workspace.v2`，官方 SDK `contest_harness 1.0.4`
**文档版本**：1.5.1（2026-11-19）

---

## 1. 运行环境

| 项 | 要求 | 说明 |
|---|---|---|
| 架构 | linux/amd64 | 镜像为单架构，`docker save` 归档，可直接 `docker load` |
| CPU | 2 核 | 训练与预测都是纯 NumPy 矩阵运算，线程固定为 1，不争抢宿主核 |
| 内存 | 4 GiB | 最坏情况（B 集 865 参数 MLP × 16 epoch）峰值 < 300 MiB |
| 工作卷 | 4 GiB | 每轮候选目录 `candidate-r{N}/` 只有 `checkpoint.npz`（< 1 MiB）与 `recipe.json` |
| GPU | 不需要 | 不使用 CUDA，不加载 torch |
| 网络 | **不需要外网** | 镜像内无模型端点、无密钥；大模型调用走平台宿主网关 |
| 系统时间 | 无要求 | 不使用时间戳做决策，避免非确定性 |
| 基础镜像 | `python:3.10-slim` | 已含 Python 3.10、pip、glibc；无额外系统包 |

离线约束的实测结论：构建阶段若容器访问 PyPI 会挂死，因此镜像构建时使用本地 wheel
（`--mount=type=bind,source=_wheels`）安装；运行阶段完全不需要网络。

## 2. 依赖清单

运行时第三方依赖只有一个：

```
numpy==1.26.4
```

镜像内已固化，版本可用 `python3 -c "import numpy;print(numpy.__version__)"` 复核。
镜像中**没有**数据、没有权重、没有密钥、没有 `.env`；`/app` 只读。

## 3. 目录与输入输出

平台挂载（只读/读写由平台控制，镜像不自建）：

| 路径 | 权限 | 内容 |
|---|---|---|
| `/data/train.jsonl` | 只读 | 本轮公开训练投影，行格式 `{"id","inputs","answer"}` |
| `/data/validation.jsonl` | 只读 | 本轮公开验证投影，格式同上；只用于监测与门禁 |
| `/previous` | 只读 | 父产物目录（上一轮 `checkpoint.npz` 与声明文件） |
| `/state` | 只读 | 平台原生状态（历史帧、计量） |
| `/model` | 只读 | 预测时挂载的最终产物 |
| `/workspace` | 可写 | 本轮唯一可写目录，写 `candidate-r{N}/` |

输入契约（`rulkit/data.py` 强校验，任何一条不满足即整轮失败并给出明确错误）：

- 每行必须是对象，且含 `id`、`inputs`、`answer` 三键；`id` 非空且全局唯一；
- `inputs` 只允许嵌套字典/列表/有限数值，叶子特征数 1..4096，深度 ≤ 16；
- 禁止出现 `rul`、`truerul`、`remainingusefullife`、`normalizedrul`、`totalsnapshots` 等目标派生字段；
- 同一训练/验证文件内特征路径序列必须完全一致（schema 变化即报 `feature schema changed`）；
- 文件必须是普通文件（非符号链接），≤ 128 MiB，UTF-8，禁止重复键与非有限数。

输出：

- `train`：在 `/workspace` 写候选产物并以 SDK 的 `SUBMIT_CANDIDATE` / `FINISH` 帧上报；
  每轮**恰好一次**真实模型调用，`finish` 必须携带该调用的 `call_id`；
- `predict`：从 stdin 逐行读样本，向 stdout 逐行写预测（分类写分数向量，回归写单值）；
- 所有日志写 stderr，不污染协议通道。

## 4. 启动命令

镜像 `ENTRYPOINT ["python3","/app/harness.py"]`，`CMD ["describe"]`。平台按以下三种方式调用：

```bash
docker run --rm zhixun-harness:1.5 describe     # 能力声明（不需要数据/模型）
docker run --rm -i zhixun-harness:1.5 train     # 一轮：stdin 收 start 帧
docker run --rm -i zhixun-harness:1.5 predict   # 逐行收样本，逐行回预测
```

本地自检（无平台驱动也能跑）：

```bash
python3 -c "import json,subprocess;print(subprocess.run(['python3','harness.py','describe'],capture_output=True,text=True).stdout)"
```

期望输出：

```json
{"protocol":"contest.harness.workspace.v2","model_access":"host_gateway_rpc",
 "sdk":"contest_harness","sdk_version":"1.0.4","tasks":["classification","regression"]}
```

## 5. 配置参数

### 5.1 环境变量（镜像已设默认值，平台一般无需覆盖）

| 变量 | 默认 | 作用 |
|---|---|---|
| `CONTEST_SUBMISSION` | `contest_submission` | 选手模块名，SDK 据此 import |
| `BASELINE_CPU_THREADS` | `1` | NumPy/BLAS 线程数，固定 1 保证确定性 |
| `OMP_NUM_THREADS` 等 | `1` | 同上，四个 BLAS 变量都置 1 |
| `CONTEST_WORK` | `/workspace` | 候选产物根目录（离线测试时可改） |
| `CONTEST_PARENT_ROOT` | 空 | 仅离线复现用：把父检查点目录指到本地 |
| `CONTEST_ARTIFACT_PATH` | 空 | 仅离线复现用：显式指定预测用的 `checkpoint.npz` |
| `ZHIXUN_LOSS` | 由配方写 | `mse` / `center`（中心化损失） |
| `ZHIXUN_WD` | 由配方写 | L2 权重衰减 |
| `ZHIXUN_SWA` | 由配方写 | 末 k 个 epoch 权重平均 |
| `ZHIXUN_SEV` | 由配方写 | 谱能量方差加权强度 |
| `ZHIXUN_SEV_END` | 由配方写 | 该加权只在末若干 epoch 生效 |
| `ZHIXUN_LS` / `ZHIXUN_JITTER` / `ZHIXUN_CLIP` | `0` / `0` / `5.0` | 标签平滑、输入抖动、梯度裁剪 |

### 5.2 四个交付配方（`contest_submission.RECIPES`）

| 配方 | loss | wd | swa | sev | end | epochs A/B/C | 用途 |
|---|---|---|---|---|---|---|---|
| `official` | mse | 0.00 | 0 | 0.0 | 否 | 3/2/8 | 官方默认，安全兜底 |
| `center035_sev2_end` | center | 0.20 | 2 | 2.0 | 是 | 3/8/12 | B 集主配方（+183.41 RMSE） |
| `center04_end` | center | 0.20 | 0 | 0.0 | 否 | 3/8/12 | B 集对照（无 SWA） |
| `long_train_swa` | mse | 0.00 | 2 | 0.0 | 否 | 5/6/14 | C 集主配方（−2.61%） |

A 集默认 `official`（A 的线性探针已证明：合规动作空间内离线上界不可达，多训无益）。
`epochs` 上限 16，大模型只能在这四个配方与 1..16 的 epoch 内选，**不能**凭空发明超参。

### 5.3 决策与门禁参数

| 参数 | 值 | 说明 |
|---|---|---|
| `max_tokens` | `min(600, 平台上限)` | 决策输出很短，600 足够容纳 JSON + 理由 |
| `temp` | `0` | 压低抖动；仍存在远端非确定性，报告中以重复实验呈现方差 |
| `min_gain` | A 0.002 / B 5.0 / C 0.5 | 门禁：增益下限 |
| `worst_tol` | 0.02 | 门禁：最差段允许的回退比例 |
| 采纳规则 | `gain ≥ min_gain` 且 `worst_gain ≥ −worst_tol×静态值` | 未通过则回退父检查点 |
| v2 门禁 | 多轨迹均值 − k·se 下界 + 配对 bootstrap 下界 > 0 | 降低单次噪声误采纳 |

### 5.4 决策输入、配方回退与版本差异（1.5.1）

| 项 | 1.5.0 | 1.5.1（当前镜像） |
|---|---|---|
| 配方空间 | 4 个配方全开，分类也可能被要求跑 center 损失 | 按任务门控：分类只 `official` / `long_train_swa`，回归 4 个 |
| 决策输入 | 行数 + 父检查点元信息 | 先测当轮检查点（accuracy+macro_f1 或 rmse+mae；无验证集时 `holdout-1/5` 探针，上限 512 行），再加数据剖面与最近 3 轮历史 |
| 失败处理 | 单次执行，异常即 round_failed | 三级回退：默认配方 → 父检查点重载换默认 → `official`；`attempts` 落盘 |
| 诊断字段 | 无 | `recipe_notes`（如 `sev_skipped:no-vertical-spectral-column`）保留进 `recipe.json` |

探针只在没有 `/data/validation.jsonl` 时使用，且只进入决策日志，不参与门禁采纳判定；
门禁仍以平台验证集为准。

## 6. 离线运行方式

1. 导入镜像（离线机器，不需要外网）：

   ```bash
   docker load -i zhixun-harness-1.5.tar
   # 归档 manifest.json 带 RepoTags，加载后即为 zhixun-harness:1.5
   docker images | grep zhixun-harness      # 期望 zhixun-harness 1.5（镜像内 label 版本为 1.5.1）
   # 若显示 <none>（个别 importer 只认 image id）再补一次命名：
   # docker tag <id> zhixun-harness:1.5
   ```

2. 校验归档完整性：

   ```bash
   sha256sum zhixun-harness-1.5.tar
   # 9ff79a47e240c0f7bb1df84de712c14090f4654139c629e66c80d9ecea9f3345
   ```

3. 无网络冒烟（不挂数据、不调模型）：

   ```bash
   docker run --rm --network none zhixun-harness:1.5 describe
   ```

4. 预测冒烟（挂一份本地 `checkpoint.npz` 与样本，`--network none` 下可完成）：

   ```bash
   docker run --rm --network none -i \
     -v $PWD/fixtures/model:/model:ro \
     zhixun-harness:1.5 predict < fixtures/samples.jsonl
   ```

5. 训练必须在平台环境内跑：模型调用由宿主网关提供（`rnd.model()`），
   镜像内既无端点也无密钥。离线机器上 `train` 会因拿不到网关而报错，属预期。

## 7. 评测复现步骤

### 7.1 复现静态基线（对照锚点）

用官方基线镜像在同一份 `/data` 投影上跑 `train`（配方 `official`）与 `predict`，
得到 A/B/C 的静态基线：**A 0.7140 / B 681.1598 / C 52.8686**。这是所有增益的分母。

### 7.2 复现本系统 10 轮结果

1. 平台侧按官方流程把镜像导入，配置任务 A/B/C 与 10 轮预算；
2. 每轮平台依次调用 `train`（注入 `/data`、`/previous`、`/workspace`），
   记录 `FINISH` 帧中的 `configuration.recipe/epochs/validation_before/validation_after`；
3. 每轮结束后用该轮产物跑 `predict`，在隐藏验证集上计分；
4. 期望结果（与提交材料一致）：

   | 数据集 | 指标 | 静态基线 | 本系统 | 增益 |
   |---|---|---|---|---|
   | A | Macro-F1 | 0.7140 | 0.7258 | +0.0086（0.44σ，不显著） |
   | B | RMSE | 681.1598 | 497.7463 | +183.41（≈20σ） |
   | C | RMSE | 52.8686 | 51.4884 | −2.61% |

5. 判定口径必须用官方公式：`G=(系统−静态)/(全量重训上界−静态)`，分段计算后取段均；
   不要用总平均掩盖最差段。

### 7.3 复现单轮决策（排查用）

离线把父检查点解到 `fixtures/parent/`，样本放到 `fixtures/`，设
`CONTEST_PARENT_ROOT`、`CONTEST_WORK`、`CONTEST_ARTIFACT_PATH` 后执行：

```bash
CONTEST_PARENT_ROOT=$PWD/fixtures/parent CONTEST_WORK=$PWD/out \
  python3 harness.py train < fixtures/start.json
```

`start.json` 为一行 JSON（含 `round_index`、`dataset_key`、`task`、`max_output_tokens` 等字段），
平台驱动会原样注入；这一步仍需要模型网关，纯离线复现只验证数据/训练/产物链路。

## 8. 异常处理

| 现象 | 退出码/日志 | 处理 |
|---|---|---|
| `PARENT_DIGEST_MISMATCH` | 非 0，stderr 含该串 | 父检查点被改动：不要手动修补元信息，重新从平台拉父产物 |
| `feature schema changed` | 非 0 | 投影 schema 与检查点不一致：说明本轮 `/data` 与父产物不同源，停止并上报 |
| `parent checkpoint task ... does not match` | 非 0 | 分类/回归任务错配：检查平台 `dataset_key` 与父产物 `meta.task` |
| 模型调用超时/失败 | `rnd.model` 抛错 | 该轮无法 `finish`（SDK 要求至少一次真实调用）：平台重试该轮；连续失败则回退 1.3 镜像 |
| 模型输出非 JSON / 配方名非法 | 正常完成 | `_parse_json` 已兜底：配方回默认值、epochs 夹到 1..16，`configuration.parse` 记录原因 |
| 验证集为空或 0 行 | 正常完成 | 监测与门禁跳过，配方回默认，仍提交候选（不阻塞评测） |
| 损失出现 NaN/Inf | 训练内部检测 | 该轮候选不提交，`finish` 回退父检查点 |
| 磁盘满 | 非 0 | 候选目录只有 <1 MiB，通常是宿主卷问题：清理 `/workspace` 后重跑 |
| 预测找不到 `checkpoint.npz` | 非 0 | `/model` 挂载为空：检查平台产物选择，或用 `CONTEST_ARTIFACT_PATH` 指定 |

所有异常都不会写坏父产物：训练只写 `/workspace`，父目录与 `/data` 全程只读。

## 9. 回滚方法

按影响面从小到大，三级回滚：

1. **回配方**（秒级，不断轮）：把 `DEFAULT_BY_DATASET` 改回
   `{"A":"official","B":"center035_sev2_end","C":"long_train_swa"}` 并令模型不可用时的兜底同此；
   即整轮退化为“已知最优配方续训”，仍是合规系统。
2. **回检查点**（单轮）：某轮候选被判不合格时，`finish` 直接回退父检查点，
   平台把该轮视为“未采纳”，历史模型的回测保持率不受影响（I1 不变量：被拒轮次不作下一轮起点）。
3. **回镜像**（分钟级）：`docker load` 官方基线镜像或本队 1.3/1.4 归档
   （`zhixun-harness-1.3.tar` 71.6 MB，入口 `python -m harness.entrypoint`），
   平台重新导入即可；1.3 与 1.5 的产物 `checkpoint.npz` 结构兼容（同为 Meta + 参数数组），
   但**不要跨版本续训**，回滚后从平台父产物重新开始。

镜像级回滚的验证：`describe` 返回 `protocol` 字段；1.3 返回旧协议，1.5 返回
`contest.harness.workspace.v2`，可据此确认当前生效版本。

## 10. 已知限制

- A 集：合规动作空间内离线上界不可达，系统只在“不劣化”一侧稳定，增益不显著（0.44σ）。
- C 集：行级 KS 统计量在“工况切换”与“P(x) 漂移”两种情形下同值，归因会退化为 `mixed`，
  合成漂移流 4 例中判对 2 例；已在项目说明书中如实披露。
- 大模型远端即使 `temperature=0` 仍有抖动，单轮结论需重复 2–3 次取均值，
  材料中的 P5 三臂对比即按此口径给出。
